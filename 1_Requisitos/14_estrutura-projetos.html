Contexto

O código das três frentes da Stack de desenvolvimento fica em 5_DEV/: o backend em C#, as aplicações web frontend-landing-page, frontend-hub e frontend-quest em Vue e os apps do hub e do quest em .NET MAUI, para Android e iOS. Sem uma estrutura comum, cada frente se organiza de um jeito e regras de domínio se misturam com HTTP, banco e tela.

A estrutura segue a arquitetura hexagonal (portas e adaptadores). Cada frente tem um core/, dividido por contexto (landing_page, hub, quest e commons) e por feature, com o domínio, os casos de uso e as portas de entrada (ports/in) e de saída (ports/out). Os runtimes usam o core e têm os adaptadores: os primários em infra/in, que recebem as chamadas, e os secundários em infra/out, que falam com o mundo externo. No backend, o runtime é o ms_mono; no frontend, é um app (apps/<app>).

Decisão do time do projeto em 2026-10-24: o backend é um único serviço, ms_mono, com todos os contextos. A web é um único projeto com três builds, um por app, que compartilham os componentes do core sem cópia nem module federation. O mobile segue o mesmo desenho, com um projeto .NET MAUI por app, que gera o Android e o iOS.

Regras de negócio

IDRegra
RN-143Backend, web e mobile seguem a mesma estrutura: core/<contexto>/<feature>/ com o domínio, os casos de uso e as portas, e runtimes com os adaptadores em infra/in/<contexto>/<feature>/ e infra/out/<contexto>/<feature>/
RN-144Os contextos são landing_page, hub, quest e commons; cada frente cria só os contextos que usa (o mobile não tem landing_page), e um contexto novo exige uma nova versão deste documento
RN-145Pastas de contexto e de feature têm nome em snake_case, igual em todas as frentes: a feature hub/salas fica em core/hub/salas/ no backend, na web e no mobile
RN-146Um contexto importa somente core/commons/; ele nunca importa outro contexto, e o que dois contextos compartilham vai para core/commons/
RN-147O core/ não importa runtimes nem bibliotecas de entrada e saída (servidor HTTP, cliente HTTP, banco, cache, armazenamento do dispositivo); no frontend, só components/ usa o framework de interface (Vue ou .NET MAUI)
RN-148usecases/ implementa as interfaces de ports/in/ e usa as de ports/out/; infra/in/ chama a feature somente por ports/in/, e infra/out/ implementa as interfaces de ports/out/
RN-149Só o runtime liga as portas aos adaptadores, no ponto de composição da injeção de dependências: Program.cs no backend, main.ts de cada app na web e MauiProgram.cs de cada app no mobile
