Contexto

O CI de CI e qualidade compila e testa o código em qualquer branch. Este documento define a etapa seguinte: com todos os jobs verdes e somente a partir da branch principal, o CI gera as imagens Docker e as envia versionadas ao Docker Hub.

Os requisitos daqui vieram de 02_ci-qualidade v05, sem alteração de conteúdo, com os mesmos IDs.

Requisitos não funcionais

IDFrenteRequisito
RNF-27PublicaçãoO CI gera quatro imagens Docker: a da API backend (backend-mono) e as das aplicações web frontend-hub, frontend-landing-page e frontend-quest (build do Vite servido como conteúdo estático)
RNF-28PublicaçãoAs imagens são enviadas ao Docker Hub somente quando todos os jobs de build, testes e qualidade passam
RNF-29PublicaçãoUm push ou merge na branch principal publica as imagens com as tags sha-<commit> e main
RNF-30PublicaçãoA tag git vX.Y.Z (SemVer) num commit da branch principal publica as imagens com as tags X.Y.Z, X.Y e latest
RNF-31PublicaçãoPush e merge em branches que não são a principal executam build e testes, sem publicar imagens
RNF-32PublicaçãoAs imagens são publicadas nos repositórios públicos do Docker Hub gustavoboaz/backend-mono, gustavoboaz/frontend-hub, gustavoboaz/frontend-landing-page e gustavoboaz/frontend-quest
RNF-33PublicaçãoO CI se autentica no Docker Hub com um token de acesso pessoal da conta gustavoboaz, com permissão de leitura e escrita, guardado em DOCKERHUB_USERNAME e DOCKERHUB_TOKEN num environment do GitHub restrito à branch principal
