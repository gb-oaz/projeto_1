Contexto

O CI de CI e qualidade testa o código e, aprovado, envia as imagens ao Docker Hub (Publicação das imagens). Este documento define a etapa seguinte: o workflow de CD pede uma segunda aprovação e, aprovado, implanta essas imagens na Azure com Terraform, em dois ambientes — homologação, com uma unidade de cada componente e sem escala, e produção, com escala parametrizada.

Premissas: tudo roda na Azure; o Terraform é um único módulo raiz, sem módulos próprios, e os ambientes diferem só nos arquivos de variáveis. Localmente o projeto usa MongoDB e Redis (Stack de desenvolvimento RNF-06); na Azure eles são o Cosmos DB for MongoDB e o Azure Managed Redis, compatíveis com os mesmos clientes. Monitoramento e custos (Log Analytics, Application Insights e orçamentos) são serviços do grupo de recursos e não ocupam subnet: na VNet ficam só o Container Apps, os private endpoints e, em produção, o Application Gateway.

Homologação sem Application Gateway: o Application Gateway com WAF cobra por hora mesmo sem tráfego e seria o maior custo da homologação. Nela, a exposição é feita pela própria entrada HTTPS do Container Apps, sem custo fixo. Em produção ele é o único ponto público. Decisão confirmada pelo dono do projeto em 2026-10-13.

Regras de negócio

IDRegra
RN-17Existem dois ambientes, cada um numa assinatura Azure própria com um grupo de recursos: homologação na assinatura deb-boaz-app-hml (grupo deb-boaz-app-hml_rg) e produção na deb-boaz-app-prd (grupo deb-boaz-app-prd_rg)
RN-18Um merge na branch principal implanta em homologação as imagens sha-<commit> publicadas por ele
RN-19Uma tag vX.Y.Z implanta as imagens X.Y.Z publicadas por ela primeiro em homologação e, depois, em produção
RN-25A etapa de produção de uma tag só começa depois que a mesma tag foi implantada e verificada em homologação; se a etapa de homologação falhar ou for negada, a tag não chega a produção
RN-20Nenhuma implantação acontece sem aprovação manual, pedida somente depois que as imagens foram publicadas; cada ambiente tem a sua aprovação, inclusive nas duas etapas de uma tag
RN-21Componente sem imagem nova na execução mantém a imagem que já está implantada
RN-22Homologação valida uma unidade de cada componente: nunca escala a zero e não é dimensionada para carga
RN-23Toda mudança de infraestrutura passa pelo Terraform do repositório; alteração manual no portal é desfeita na implantação seguinte
RN-24Segredo nunca fica no código, nos arquivos de variáveis do Terraform nem em texto no workflow: fica no Key Vault do ambiente

O CD roda em executores hospedados do GitHub, fora da VNet. Para que o Terraform grave segredos, o Key Vault mantém o acesso público ligado, restrito por RBAC à identidade do CD; as aplicações o leem pelo private endpoint. Fechá-lo de vez exige um executor dentro da VNet.
